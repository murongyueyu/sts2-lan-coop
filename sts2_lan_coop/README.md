# STS2 LAN Co-op · 使用说明

版本 **0.3.0-alpha.1**，目标游戏 **v0.107.1**，当前仅支持 Windows 入口。

**全员必须使用同版 Mod（准入协议 3）**；0.2、手机内置 LAN 和更早版本不能直接混用。

## 安装与回退

1. 退出游戏，备份整个游戏用户存档目录。建议先使用独立测试配置。
2. 解压安装包，将 `sts2_lan_coop` 目录放进游戏 `mods` 目录，DLL 与同名 JSON 放在一起。
3. 只启用一个 LAN Mod，完整重启；不要叠加 `sts2_lan_connect` 等网络补丁。
   新版已内置快速 SL，请**禁用外部 QuickSL** 再重启；JmcModLib 如被其他 Mod 依赖可保留，不要求卸载。
4. 打开多人菜单右上角「局域网 / 直连 · 4 人」。

回退前退出游戏、整体备份存档库，再将当前 Mod 移出 `mods`。0.2 可继续使用原存档库，但不能加入 0.3 房间；更早版本不提供该存档列表。

## 新建与保存

主机填写昵称、UDP 监听端口和对局名称，再点击「创建四人房间」。房间最多四人，实际 2、3 或 4 人准备开局；这个实际人数会固定在存档中。

原版产生保存点时，主机会将完整原版存档归档到本 Mod 的独立存档库。暂停菜单的「保存并退出」会等待保存结束并验证归档；归档失败时弹出错误并保留当前对局。保存点沿用原版规则，退出不意味着能在战斗任意一步建立即时快照。首次有效保存点之前可能提示稍后重试。

不同新对局使用不同存档 ID。名称可以相同，修改名称不会改写角色或进度。存档列表包含人数、幕、层数和保存时间。每个保存修订保留旧载荷，目前不自动清理历史修订，请留意长期使用后的磁盘占用。

## 主机继续对局

在连接面板的「继续多人对局」中找到要玩的存档，可编辑名称后点击「保存名称」，再点击「继续此对局」。需要时点击「刷新存档列表」。

主机始终使用原来主机的角色。大厅显示已到人数，**人数恰好等于开局人数、所有角色都有人且全部准备后才开始**。两人存档缺一人不能继续，三人存档只到两人也不能继续。

本版只归档与读取普通 LAN 存档，要求原版主机槽位 ID 为 1、人数 2–4。无法识别或校验失败的存档保留原文件并报错，不静默删除或覆盖。Steam 原生联机及其他 Mod 改造的存档不保证能导入。

## 客机加入、换人和互换

填写本次使用的昵称、房主地址，点击「查看房间 / 刷新可选角色」。新房间可以直接连接；继续中的存档会列出全部已有角色和生命、金币、遗物、牌组、药水信息。

主机角色显示为锁定。客机选择一个空闲的已有角色，再点击「连接」，进入原版读档准备大厅。角色包括完整存档状态，不能重新捏造角色替换该进度。

例如主机与 A 保存后，下次可由 B 认领 A 原来的角色，A 不需要在线；主机 + A + B 保存后，下次 A、B 可分别选择对方原来的角色。当前玩家的昵称显示给所有人，并跟随当前玩家。

同一角色不能同时被两人认领，在线角色不能被抢占。连接时短时预留 30 秒，取消或失败后未使用的预留会到期释放，可刷新后重试。

## 快速 SL（保持当前角色）

在对局暂停菜单点击「快速 SL · 全员重载」，或按默认快捷键 **Ctrl+F8**。主机直接发起；客机按键会申请，主机确认后全员一起重载当前这局最近的有效保存点。成功时保留网络连接，不用返回主菜单、重新连接、准备或选择角色。

**快速 SL 完全不提供换角色。** 主机与客机都保持本次的角色、昵称和完整绑定；想换角色必须「保存并退出 → 主机继续这局 → 客机重新认领角色」。人数必须原开局人数全部在线，缺人时不会缩小到在线集合继续。

SL 不额外把当前画面保存掉，只等待已经开始的保存完成后固定有效保存点。效果参照手动保存退出再继续：未持久化操作可以重做，不保证所有选项重置，也不保证随机结果改变。不能在没有保存点、切场景中或另一次 SL 进行中发起。

连接面板底部可修改快捷键，例如 `Alt+F8`、`Ctrl+Shift+F9`，点击「保存联机和快捷键设置」。填写 `off` 只关闭快捷键，暂停菜单按钮仍保留；输入文本时不触发快捷键。

进度浮层显示当前阶段、已就绪人数和等待的昵称；进入清理旧场景前可取消，开始重载后不提供中途取消。数据分块校验和全员加载完成后才解锁；失败若已销毁旧场景，将保留恢复点并回到菜单，需原人数重新组队。阶段超时 30 秒，不保证固定秒数完成。

## Radmin 与樱花

两种方式均保留，游戏及 Mod 资料共用一个 UDP 端口（默认 33771），不需要另开角色选择 TCP 端口。

- **实体 LAN**：填写房主可达的局域网 IP。
- **Radmin**：加入相同虚拟网络，填写房主 Radmin IP 和游戏监听端口。
- **樱花**：房主创建 UDP 隧道，映射实际游戏监听端口；客机填写节点域名和外部 UDP 端口。邀请面板可以保存、复制外部地址，但不会自动创建隧道。

连接可取消，房间资料请求最多 12 秒，实际入房流程总体 20 秒。穿透不保证降低延迟；保留原版版本、玩法 Mod 和模型哈希检查，不关闭这些检查来掩盖差异。

## 数据和边界

- **配置**：`user://sts2_lan_coop/settings.json`，持久玩家 ID 与本次角色槽位 ID 分开。不要为了换角色手改 PlayerId。
- **存档库**：`user://sts2_lan_coop/catalog/<账号与配置标识>/`，包含每局 manifest、revisions 中的原版载荷与摘要。另有原版当前多人工作存档。应整体备份存档库，单独备份 DLL 不能恢复游戏进度。
- `user://` 指 Godot 用户目录，Windows 通常位于 `%APPDATA%\SlayTheSpire2`。

未完成验收：手机加载、跨设备樱花联机、长期高延迟、完整整局及所有显示缩放。暂不支持运行中接入/换人、人数增减、主机密码房。自动化使用本机独立游戏副本及测试用户目录，不代表这些实机场景通过。
