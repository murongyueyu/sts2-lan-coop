# 开发版使用说明

版本：**0.7.0-alpha.6**，同一DLL支持游戏 **v0.107.1 / v0.111.0**。房主直传使用16分片窗口和二进制传输，界面显示本次平均MiB/s；不需要云账号或新增端口。PC与手机均须完整更新并重启：准入5、SL控制2、同步协议2（不兼容alpha.5同步协议1）。按用户要求本轮仅编译/静态核查，未做模拟测试，等待用户实测。安卓仍为全员SL及主机模组比较/下载后手动导入，自动应用仍仅Windows支持，见[提速实测说明](模组直传提速_实现与实测说明.md)。

## 安装与回退

1. 退出游戏，备份整个游戏用户存档目录。建议先使用独立测试配置。
2. 解压安装包，将完整`sts2_lan_coop`目录放进游戏`mods`目录，保留DLL、同名JSON和`Apply-ModSync.ps1`本地应用助手。
3. 只启用一个LAN Mod，完整重启；不要叠加`sts2_lan_connect`等网络补丁。
   新版已内置快速SL，请禁用外部QuickSL再重启；JmcModLib如被其他Mod依赖可保留，不要求卸载。
4. 打开多人菜单右上角「局域网 / 直连 · 4人」。

构建脚本不会自动安装或改防火墙。回退前退出游戏、整体备份存档库，再将当前Mod移出mods并解压旧包。0.2可继续使用原存档库，但不能加入0.3房间；更早版本不提供该存档列表。历史包仍在`releases`目录。

## 新建与保存

新增「共用原版 / 模组解锁（进行中的对局分开）」，位于本Mod联机面板，默认关闭。关闭其他游戏实例、退出当前对局/房间后，确认「备份并开启」；以后加载模组进度时合并原版解锁，保存时导出新增原版解锁，下次打开无模组版生效。只处理当前账号同编号存档栏；战绩、成就记录、设置、单人/多人对局及模组专属内容分开。关闭不撤销已有合并，备份/恢复与边界见[共用解锁说明](原版与模组共用解锁_实现与验证.md)。

模组不同先使用「检查 / 同步主机模组」：主机可勾选有权分享文件，客机明确确认新增/替换/禁用。文件已安装但未启用时，只弹窗询问是否启用并重启，无需下载。需要下载时可选主机直传，Steam能力可用时另有工坊选项；文件必须与主机版本和指纹一致。确认退出后助手备份并应用，重启打开面板复核、再连接。多余模组禁用，不删除或退订；完整步骤和限制见[同步使用与验证](主机模组同步_实现与验证.md)。

主机填写昵称、UDP监听端口和对局名称，再点击「创建四人房间」。房间最多四人，实际2、3或4人准备开局；这个实际人数会固定在存档中。

原版产生保存点时，主机会将完整原版存档归档到本Mod的独立存档库。暂停菜单的「保存并退出」会等待保存结束并验证归档；归档失败时弹出错误并保留当前对局。保存点沿用原版规则，退出不意味着能在战斗任意一步建立即时快照。首次有效保存点之前可能提示稍后重试。

不同新对局使用不同存档ID。名称可以相同，修改名称不会改写角色或进度。存档列表包含人数、幕、层数和保存时间。每个保存修订保留旧载荷，目前不自动清理历史修订，请留意长期使用后的磁盘占用。

## 主机继续对局

在连接面板的「继续多人对局」中找到要玩的存档，可编辑名称后点击「保存名称」，再点击「继续此对局」。需要时点击「刷新存档列表」。

主机始终使用原来主机的角色。大厅显示已到人数，**人数恰好等于开局人数、所有角色都有人且全部准备后才开始**。两人存档缺一人不能继续，三人存档只到两人也不能继续；没有“缺人也继续”的确认入口。

本版只归档与读取普通LAN存档，要求原版主机槽位ID为1、人数2–4。无法识别或校验失败的存档保留原文件并报错，不静默删除或覆盖。旧LAN原版工作存档在新建/加入前会先归档。Steam原生联机及其他Mod改造的存档不保证能导入。

## 客机加入、换人和互换

填写本次使用的昵称、房主地址，点击「查看房间 / 刷新可选角色」。新房间可以直接连接；继续中的存档会列出全部已有角色和生命、金币、遗物、牌组、药水信息。

主机角色显示为锁定。客机选择一个空闲的已有角色，再点击「连接」，进入原版读档准备大厅。角色包括完整存档状态，不能重新捏造角色替换该进度。角色列表显示保存时的本地化名称，旧摘要缺少名称时显示游戏模型标识。

例如主机与A保存后，下次可由B认领A原来的角色，A不需要在线；主机+A+B保存后，下次A、B可分别选择对方原来的角色。当前玩家的昵称显示给所有人，并跟随当前玩家；不会沿用该角色的旧操作者昵称。

同一角色不能同时被两人认领，在线角色不能被抢占。连接时短时预留30秒，取消或失败后未使用的预留会到期释放，可刷新后重试。要重新选角色应先离开大厅，再刷新选择。

## 手机端加入（Android，期1）

手机接入已由用户确认。手机与PC请同时更新完整alpha.6包并重启，不能和旧版混用同步协议。连接前读取主机模组清单，版本/文件/启用状态不同会给出明确提示，游戏版本/玩法/模型校验继续生效。比较下载速度时使用尚未完整缓存的包，已有完整缓存会直接复用，不能据此判断网络吞吐。

- 可用：「连接」「查看房间 / 刷新可选角色」、昵称设置、暂停菜单“申请全员快速SL”、参与主机发起的全员SL。
- 可用：“检查 / 下载主机模组（手动导入）”。确认后下载主机PC包到独立缓存；只校验包完整性，不承诺Android兼容，不自动安装或启用。
- 禁用：手机建房与“继续此对局”、自动应用/恢复模组配置、共用解锁。

下载后可复制缓存路径，在启动器文件浏览器定位/导出ZIP；退出游戏后，确认对应模组支持Android，再用启动器导入/启用并重启。仅启用状态不同不下载，提示手动调整。缓存为`user://sts2_lan_coop/modsync/cache`，界面显示实际路径；不放进mods扫描目录，不覆盖已加载DLL/PCK。启动器v0.1.11尚无本Mod已接入的扫描前事务接口，因此这不是完整自动同步；不同平台构建不能只按模组ID和版本号相同导入。

手机SL要求前台、原人数到齐及全员准备成功；后台/取消/错误在commit前保留当前对局，commit后按全队停止恢复存档处理。新增阶段耗时和托管内存日志，仍保留30秒阶段时限。尚待真机验收：SL触屏与场景重建、后台路径、文件下载/导出/导入、实际第三方模组兼容及整局稳定性。

## 快速SL（保持当前角色）

在对局暂停菜单点击「快速SL · 全员重载」，或按默认快捷键 **Ctrl+F8**。主机直接发起；客机按键会申请，主机确认后全员一起重载当前这局最近的有效保存点。成功时保留网络连接，不用返回主菜单、重新连接、准备或选择角色。

**快速SL完全不提供换角色。** 主机与客机都保持本次的角色、昵称和完整绑定；想换角色必须「保存并退出→主机继续这局→客机重新认领角色」。人数必须原开局人数全部在线，缺人时不会缩小到在线集合继续。

SL不额外把当前画面保存掉，只等待已经开始的保存完成后固定有效保存点。效果参照手动保存退出再继续：未持久化操作可以重做，不保证所有选项重置，也不保证随机结果改变。不能在没有保存点、切场景中或另一次SL进行中发起。

连接面板底部可修改快捷键，例如`Alt+F8`、`Ctrl+Shift+F9`，点击「保存联机和快捷键设置」。填写`off`只关闭快捷键，暂停菜单按钮仍保留；输入文本时不触发快捷键。

进度浮层显示当前阶段、已就绪人数和等待的昵称；进入清理旧场景前可取消，开始重载后不提供中途取消。数据分块校验和全员加载完成后才解锁；失败若已销毁旧场景，将保留恢复点并回到菜单，需原人数重新组队。阶段超时30秒，不保证固定秒数完成。

更多实测及边界见[快速SL实现与验证](多人快速SL_实现与验证.md)。

## Radmin与樱花

两种方式均保留，游戏及Mod资料共用一个UDP端口（默认33771），不需要另开角色选择TCP端口。

- 实体LAN：填写房主可达的局域网IP。
- Radmin：加入相同虚拟网络，填写房主Radmin IP和游戏监听端口。
- 樱花：房主创建UDP隧道，映射实际游戏监听端口；客机填写节点域名和外部UDP端口。邀请面板可以保存、复制外部地址，但不会自动创建FRP隧道。

连接可取消，房间资料请求最多12秒，实际入房流程总体20秒。穿透不保证降低延迟；保留原版版本、玩法Mod和模型哈希检查，不关闭这些检查来掩盖差异。

## 数据和边界

配置：`user://sts2_lan_coop/settings.json`，持久玩家ID与本次角色槽位ID分开。不要为了换角色手改PlayerId。

存档库：`user://sts2_lan_coop/catalog/<账号与配置标识>/`，包含每局manifest、revisions中的原版载荷与摘要。另有原版当前多人工作存档。应整体备份存档库，单独备份DLL不能恢复游戏进度。昵称随会话同步，不以旧操作者昵称锁定角色。

`user://`指Godot用户目录，Windows通常位于`%APPDATA%\SlayTheSpire2`。本版使用原版SaveManager的账户实际路径读取工作存档，避免将不同账户或profile混在一起。

未完成验收：手机面板按钮、查看房间、真机进房、模组集合不一致提示、失败/取消/超时、设置与存档库写盘、跨设备樱花联机、长期高延迟、完整整局及所有显示缩放。暂不支持运行中接入/换人、人数增减、主机迁移、密码房。自动化使用本机独立游戏副本及测试用户目录，不代表这些实机场景通过。
