# 开发版使用说明

版本：**0.8.0-alpha.3**，支持游戏 **v0.107.1 / v0.111.0**。本版修复扩展保存后的工作档误报，并新增「处理工作档冲突」入口：先完整备份主档、备份档和租约，再恢复 LAN 借用前的工作槽。PC与手机须统一完整包并重启：准入5、SL2、同步2保持；本地存档Schema1可读、Schema2写入。证据与未验收边界见[工作档冲突修复记录](工作档冲突修复_0.8.0-alpha.3.md)。这是未自动安装／发布的开发包，Android真机与真实Steam流程需要另行验收。

## 安装与回退

1. 退出游戏，备份整个游戏用户存档目录。建议先使用独立测试配置。
2. 解压安装包，将完整`sts2_lan_coop`目录放进游戏`mods`目录，保留DLL、同名JSON、`Apply-ModSync.ps1`同步助手和`Organize-Workshop.ps1`工坊整理助手。
3. 只启用一个LAN Mod，完整重启；不要叠加`sts2_lan_connect`等网络补丁。
   新版已内置快速SL，请禁用外部QuickSL再重启；JmcModLib如被其他Mod依赖可保留，不要求卸载。
4. 打开多人菜单，选择「Steam 联机」或「局域网 / 直连」页签。LAN页提供「创建房间」「加入房间」「继续对局」，管理操作位于「联机设置」。

构建脚本不会自动安装或改防火墙。回退前退出游戏、整体备份存档库，再将当前Mod移出mods并解压旧包。0.2可继续使用原存档库，但不能加入0.3房间；更早版本不提供该存档列表。历史包仍在`releases`目录。

## 新建与保存

新增「共用原版 / 模组解锁（进行中的对局分开）」，位于本Mod联机面板，默认关闭。关闭其他游戏实例、退出当前对局/房间后，确认「备份并开启」；以后加载模组进度时合并原版解锁，保存时导出新增原版解锁，下次打开无模组版生效。只处理当前账号同编号存档栏；战绩、成就记录、设置、单人/多人对局及模组专属内容分开。关闭不撤销已有合并，备份/恢复与边界见[共用解锁说明](原版与模组共用解锁_实现与验证.md)。

模组不同先使用「检查 / 同步主机模组」：主机可勾选有权分享文件，客机明确确认新增/替换/禁用。文件已安装但未启用时，只弹窗询问是否启用并重启，无需下载。需要下载时可选主机直传，Steam能力可用时另有工坊选项；文件必须与主机版本和指纹一致。确认退出后助手备份并应用，重启打开面板复核、再连接。多余模组禁用，不删除或退订；完整步骤和限制见[同步使用与验证](主机模组同步_实现与验证.md)。

主机填写昵称、UDP监听端口和对局名称，再点击「创建房间」。房间最多四人，实际2、3或4人准备开局；这个实际人数会固定在存档中。

原版产生保存点时，主机会将完整原版存档归档到本Mod的独立存档库。暂停菜单的「保存并退出」会等待保存结束并验证归档；归档失败时弹出错误并保留当前对局。保存点沿用原版规则，退出不意味着能在战斗任意一步建立即时快照。首次有效保存点之前可能提示稍后重试。

不同新对局使用不同存档ID。名称可以相同，修改名称不会改写角色或进度。存档列表包含人数、幕、层数和保存时间。活跃对局保留最近3个修订及被SL／旧格式迁移固定的恢复点；删除／结束时回收该局全部续玩载荷。

## 客机接管多人旧存档

房主在「继续对局」选择存档后开房；客机在「加入房间」填写地址并点击「连接房间」。旧存档会打开独立的「选择接管角色」页：主机角色锁定，已连接或预留的角色不可选；选择空闲卡片后显示金色边框以及卡组、遗物摘要，再点击「确认角色并加入」。

「刷新角色」重新查询占用状态；确认前也会复查，最终由主机执行预留校验。浏览或返回不占用角色。主机更换房间／存档时需要返回后重新查看。接管继承该角色保存的血量、金币、卡组与遗物，显示当前连接者昵称；快速SL保持已接管的角色。新建对局仍走原版选角，不显示此页。

## 单人存档与快速SL

主菜单「继续」或单人页「选择存档」打开单人列表，可以继续、重命名、删除或新建另一局。原有有效普通冒险工作档首次打开时接入，正常保存继续更新同一局；新开冒险不会覆盖已经归档的其他局。每日／自定义单人冒险维持原版，不启用本版单人库及SL。

暂停菜单中的按钮统一叫「快速SL」。单人直接重载当前局最近有效保存点；LAN主机协调全员，客机点击同名按钮向主机申请。仍保留快捷键，不改变角色。没有有效保存点、保存／切场景中或已结束时会说明原因，不创建任意时刻的即时快照。

## 删除与结束清理

存档页「删除存档」二次确认后清理指定未使用的对局及全部历史修订，不清理战绩、解锁和其他局。活动对局或读档大厅预留中的档不能直接删。读取异常的条目可单独处理；清理失败显示原因，进入管理页会重试。

确认原版终局已完成后自动清理对应续玩归档；保存退出、断线、SL内部清理和单个队员倒下不视为整局结束。未知接力结局及没有明确结束证据的旧归档保留，可手动管理。当前LAN持久归档由主机持有，不要求离线客机在线才能管理。

卡组和遗物预览每类最多展示6项，超出显示“等……”。同一摘要卡牌合并计数，例如打击(5)，升级等级分开；完整保存内容不变。

## 工作档冲突处理

正常退出 LAN 后，本 Mod 会把借用的原版多人工作槽恢复到借用前状态。若期间有其他进程、云同步或带追加写入的扩展（如 JmcModLib 的 `_jml` 数据）改动了工作档或 `.backup`，而本 Mod 没有登记到这份字节，会保留双方并在「继续多人对局」提示「多人工作档或备份出现未记录的写入」。

1. 完全退出游戏，关闭其他游戏实例；**不要手动删除** `.backup`、工作档或 `user://sts2_lan_coop/working/` 下的租约记录。
2. 重新启动，进入多人菜单 → 局域网 / 直连 → 继续对局。
3. 点击「处理工作档冲突」，阅读确认弹窗后点「备份并恢复」。
4. 成功后显示独立备份目录 `user://sts2_lan_coop/working-conflicts/<存档范围>/<时间>-<随机>/`，内含 `lease.json`、`current_run_mp.save`（如有）和 `.backup`（如有）。未知附加数据只保存在备份中，不会自动导入，也不删除已归档对局。
5. 恢复完成后重新打开存档列表，选择要玩的存档继续。

本版同时修复了 JmcModLib 等扩展在原版保存任务结束后追加数据造成的误报：保存钩子在原版轮换 `.backup` 之前登记实际写入的完整字节，归档则在扩展追加结束后执行。普通 LAN 正常退出不再误报，只有真正未登记的写入才会提示冲突。

## 0.8.0回退提醒

旧LAN库成功续存后写入Schema2并保留旧清单／有效修订。alpha.8不能直接读取新清单。回退须先退出游戏并显式恢复对应备份；可能恢复旧进度，不能直接替换DLL后继续。新单人库单独存放，停用Mod后原版只展示当前工作存档，不会自动浏览归档列表。

## 主机继续对局

在LAN页的「继续对局」中选择要玩的存档，可编辑名称后点击「保存名称」，再点击「继续此对局」。需要时点击「刷新存档列表」。

主机始终使用原来主机的角色。大厅显示已到人数，**人数恰好等于开局人数、所有角色都有人且全部准备后才开始**。两人存档缺一人不能继续，三人存档只到两人也不能继续；没有“缺人也继续”的确认入口。

本版只归档与读取普通LAN存档，要求原版主机槽位ID为1、人数2–4。无法识别或校验失败的存档保留原文件并报错，不静默删除或覆盖。旧LAN原版工作存档在新建/加入前会先归档。Steam原生联机及其他Mod改造的存档不保证能导入。

## 客机加入、换人和互换

填写本次使用的昵称、房主地址，点击「查看房间」。新房间可以直接连接；继续中的存档会列出全部已有角色和生命、金币、遗物、牌组、药水信息。

主机角色显示为锁定。客机选择一个空闲的已有角色，再点击「连接」，进入原版读档准备大厅。角色包括完整存档状态，不能重新捏造角色替换该进度。角色列表显示保存时的本地化名称，旧摘要缺少名称时显示游戏模型标识。

例如主机与A保存后，下次可由B认领A原来的角色，A不需要在线；主机+A+B保存后，下次A、B可分别选择对方原来的角色。当前玩家的昵称显示给所有人，并跟随当前玩家；不会沿用该角色的旧操作者昵称。

同一角色不能同时被两人认领，在线角色不能被抢占。连接时短时预留30秒，取消或失败后未使用的预留会到期释放，可刷新后重试。要重新选角色应先离开大厅，再刷新选择。

## 手机端加入（Android，期1）

手机接入已由用户确认。手机与PC请同时更新完整alpha.8包并重启；LAN核心仍须同版同文件。连接前逐个核验必需模组，显示具体缺失文件、大小或SHA256差异；游戏版本/玩法/模型校验继续生效。共享目录中的相邻模组不会算入当前模组，启动器清单别名经严格核验后接受。独立美化和辅助前置不必完全相同；玩法模组依赖的前置仍必须匹配。比较下载速度应使用尚未完整缓存的包。

- 可用：「连接」「查看房间 / 刷新可选角色」、昵称设置、暂停菜单“申请全员快速SL”、参与主机发起的全员SL。
- 可用：“检查 / 下载主机模组（手动导入）”。确认后下载主机PC包到独立缓存；只校验包完整性，不承诺Android兼容，不自动安装或启用。
- 禁用：手机建房与“继续此对局”、自动应用/恢复模组配置、共用解锁。

下载后导出`user://sts2_lan_coop/modsync/import`中的ZIP：启动器 → 设置 → 系统 → 查看文件 → sts2_lan_coop → modsync → import，长按ZIP导出到共享存储，再通过启动器的模组管理导入/启用，重启游戏。每个ZIP有模组ID文件夹。`cache`保留校验用原包，新导入请用`import`目录中的包。显示隐藏文件不能打开应用私有目录，应使用启动器自带浏览器。仅启用状态不同仍提示手动调整；自动应用尚未接入，不覆盖运行中的DLL/PCK，也不承诺PC包自动兼容Android。旧版散装导入可先直接重试连接；若要整理为文件夹，重新生成/导入新包时在启动器选择替换同ID旧模组。无需清空全部模组或存档。

如果仍有差异，可从同一浏览器导出`sts2_lan_coop/modsync/last-comparison.json`查看具体文件。此报告只保存在本机。

文件已一致但仍为共用目录时，点击“检查 / 下载主机模组”可自愿生成独立目录导入包，复用完整缓存，缺少缓存才下载。仅点击“连接”不会强迫整理。

alpha.8先完成获取和主机房间复核，再本地生成导入包；本地打包阶段不再请求主机。此前超时留下的完整缓存及已生成ZIP不清除，重试会校验复用。若已显示“下载校验完成，未安装”，可直接按提示导入，无需因之前一次超时重新下载；若仍失败，请保留新提示中的阶段、操作及握手/发送状态。

## Steam工坊原目录整理

Windows多人面板点击“整理 Steam 工坊原目录（退出后执行）”，检查预览列表后确认。先暂停Steam下载/更新；游戏退出后，助手备份完整条目，再把文件移至`workshop/content/2868840/工坊编号/模组ID/`，随后重启。工坊数字目录、订阅和启用项保留，本机游戏mods目录不做整理操作。多模组、版本分支、已有嵌套结构或目标冲突的条目会跳过并提示原因。

“恢复最近一次工坊目录整理”可退出后恢复；整理/恢复遇到文件被更新、路径冲突或校验失败时停止，保留备份及错误记录。备份和日志位于游戏目录`.sts2-lan-modsync/organization/事务ID/`，重启后打开面板会显示最近结果。Steam后续更新可能恢复原散装文件结构，出现重复清单时应先检查文件，不能反复盲目整理。本功能已编译但未实际执行验收。

手机SL要求前台、原人数到齐及全员准备成功；后台/取消/错误在commit前保留当前对局，commit后按全队停止恢复存档处理。新增阶段耗时和托管内存日志，仍保留30秒阶段时限。尚待真机验收：SL触屏与场景重建、后台路径、文件下载/导出/导入、实际第三方模组兼容及整局稳定性。

## 快速SL（保持当前角色）

在对局暂停菜单点击「快速SL · 全员重载」，或按默认快捷键 **Ctrl+F8**。主机直接发起；客机按键会申请，主机确认后全员一起重载当前这局最近的有效保存点。成功时保留网络连接，不用返回主菜单、重新连接、准备或选择角色。

**快速SL完全不提供换角色。** 主机与客机都保持本次的角色、昵称和完整绑定；想换角色必须「保存并退出→主机继续这局→客机重新认领角色」。人数必须原开局人数全部在线，缺人时不会缩小到在线集合继续。

SL不额外把当前画面保存掉，只等待已经开始的保存完成后固定有效保存点。效果参照手动保存退出再继续：未持久化操作可以重做，不保证所有选项重置，也不保证随机结果改变。不能在没有保存点、切场景中或另一次SL进行中发起。

连接面板底部可修改快捷键，例如`Alt+F8`、`Ctrl+Shift+F9`，点击「保存联机和快捷键设置」。填写`off`只关闭快捷键，暂停菜单按钮仍保留；输入文本时不触发快捷键。

进度浮层显示当前阶段、已就绪人数和等待的昵称；进入清理旧场景前可取消，开始重载后不提供中途取消。数据分块校验和全员加载完成后才解锁；失败若已销毁旧场景，将保留恢复点并回到菜单，需原人数重新组队。阶段超时30秒，不保证固定秒数完成。

更多实测及边界见[快速SL实现与验证](多人快速SL_实现与验证.md)。

## Radmin与樱花

两种方式均保留，游戏及Mod资料共用一个UDP端口（默认33771），不需要另开角色选择TCP端口。

- 实体LAN：填写房主可达的局域网IP。
- Radmin：加入相同虚拟网络，填写房主Radmin IP和游戏监听端口。
- 樱花：房主创建UDP隧道，映射实际游戏监听端口；客机填写节点域名和外部UDP端口。邀请面板可以保存、复制外部地址，但不会自动创建FRP隧道。

连接可取消，房间资料请求最多12秒，实际入房流程总体20秒。穿透不保证降低延迟；保留原版版本、玩法Mod和模型哈希检查，不关闭这些检查来掩盖差异。

## 数据和边界

配置：`user://sts2_lan_coop/settings.json`，持久玩家ID与本次角色槽位ID分开。不要为了换角色手改PlayerId。

存档库：`user://sts2_lan_coop/catalog/<账号与配置标识>/`，包含每局manifest、revisions中的原版载荷与摘要。另有原版当前多人工作存档。应整体备份存档库，单独备份DLL不能恢复游戏进度。昵称随会话同步，不以旧操作者昵称锁定角色。

`user://`指Godot用户目录，Windows通常位于`%APPDATA%\SlayTheSpire2`。本版使用原版SaveManager的账户实际路径读取工作存档，避免将不同账户或profile混在一起。

未完成验收：手机面板按钮、查看房间、真机进房、模组集合不一致提示、失败/取消/超时、设置与存档库写盘、跨设备樱花联机、长期高延迟、完整整局及所有显示缩放。暂不支持运行中接入/换人、人数增减、主机迁移、密码房。自动化使用本机独立游戏副本及测试用户目录，不代表这些实机场景通过。
